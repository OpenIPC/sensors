# IMX334 driver on Infinity6E (experimental HDR registration)

This source is the RC5 driver previously tested on an SSC338Q/Star6E camera
with a four-lane IMX334 and Linux 4.9.84, renamed to sensor_imx334_mipi.c.

## Provenance

The existing SigmaStar notice is retained. Sensor-specific metadata, register
tables, orientation data and timing constants were reconstructed from factory
imx334_MIPI.ko, SHA-256:
`3a853bb093d59f15416e415046e5d76673040bb41219065bfbbbad232e46bb74`.
The driver uses SigmaStar interfaces and follows the existing OpenIPC IMX415
maximum-rate-per-resolution pattern. This submission does not assert that the
repository license overrides the per-file notice. Maintainer review of source
provenance and distribution requirements is requested.

Factory IQ, firmware dumps, U-Boot changes and credentials are excluded. Tests
used a separately extracted daytime IQ profile; equivalent image quality needs
a compatible profile.

## Prior hardware validation

| Output | Maximum fps | RC5 RAM regression measured fps |
|---|---:|---:|
| 3840x2160 | 30 | 30.27 |
| 2592x1944 | 45 | 45.24 |
| 2560x1440 | 50 | 50.23 |
| 1920x1080, full-FOV 2x2 binning | 120 | 60.07 / 90.22 / 120.27 |

These are existing short RC5 hardware tests, not a fresh hardware validation of
the upstream build. High-resolution tests used H.265 and 1080p used H.264, with
board-side VENC set to 480 MHz. Recorded windows had no additional ISP FIFO-full
events or VENC output drops. Extended thermal qualification remains pending.
The 5MP and 1440p modes use sensor windows; not every mode preserves full FOV.
HDR entry functions are restored and registered experimentally, but HDR has not
been hardware validated. The measurements above apply only to linear mode.
2K60 caused FIFO overflows
with both codecs and is excluded.

## Build and limitations

Use the SigmaStar Makefile with SENSOR_VERSION=infinity6e and
OPENIPC_SNS_MODEL=imx334, a matching prepared 4.9.84 kernel and ARM hard-float
toolchain. The wildcard object selection picks up sensor_imx334_mipi.c.
Follow the firmware build recipe for include paths and sensor_config.c.

Before HDR restoration, the linear-only source and upstream IMX335/IMX415 compiled
together without compiler or MODPOST warnings against OpenIPC/sensors commit
`ec4956a0ef45c787658f3618e0e892d37e49d677` headers and the prepared 4.9.84
kernel. The ARM EABI5 IMX334 module SHA-256 was
`ca0c304735ceabbf12a5c966b9af16b277617411b9d7df97552a3e63fc8f0221`.
This was a compile check, not a module-load test.

After restoring and registering HDR callbacks, the same four-module build
completed without compiler or MODPOST warnings. The new IMX334 module SHA-256 is
`4b0f59d7bb443261ff88236e8ae810b42d74f0cc19a95ff269f73c5705d6d4a4`.
This experimental module has not been deployed to the camera.

Like IMX335/IMX415, this driver requires the vendor sensor registration interfaces
and intlog10. They are exported by mhal.ko, not implemented by the sensor driver.
An isolated build needs its SDK symbol table via KBUILD_EXTRA_SYMBOLS. The local
CONFIG_MODVERSIONS=n build reconstructed 713 real exports by checking mhal's
ELF32 ARM .rel__ksymtab entries against __ksymtab_strings (zero CRCs are used only
for this non-versioned kernel). No missing symbols were invented and no warning
suppression flags were added. For CONFIG_MODVERSIONS=y, use original SDK CRCs.
The checked mhal.ko SHA-256 is
`0611471e7a87dd325fbc96b4548d6e3f3f710ed3a46925ef7207ca1b4cd75971`.

Unused experimental linear entry functions remain removed. HDR functions and
mode descriptors were restored from the RC5-derived source, and both SEF1 and
LEF callbacks are now registered using the same registration macro pattern as
upstream IMX335/IMX415. This is not a claim of working HDR: DOL timing, pipeline
configuration, exposure and HDR IQ still need hardware validation. Registration
alone does not switch the running camera or Majestic into HDR mode. The linear
mode descriptors and register tables have not been changed.

Majestic may constrain ONVIF GetOptions to the current mode, reject upward frame
rates or disallow codec changes within a profile. The RC5 firmware also used a
configuration watcher to restart the video pipeline. That integration is not
included in this driver-only submission. IQ selection and VENC clock setup are
separate board concerns.

## IMX415 cross-check

Reference: infinity6e/sensor_imx415_mipi.c at upstream commit ec4956a.
This is a source-level comparison, not evidence of working IMX334 HDR.

| Area | IMX334 decision |
|---|---|
| Registration | Same BEGIN_EX/END_EX pattern, linear + SEF1 + LEF callbacks. |
| Mode enumeration | Preserve IMX334 linear and HDR descriptors; no IMX415 geometry copied. |
| Mode selection | SEF chooses the physical HDR init table/timing; LEF records its mode index, as in the reference structure. |
| Initialization | Add VTS cache initialization to SEF, matching the reference's initialization on both HDR handles. |
| MIPI | Keep SONY_DOL/RAW10/four lanes; IMX415 uses DCG (VC) / RAW12 here, which is not interchangeable. |
| Clock / timing | Preserve IMX334 MCLK, HMAX, VMAX, line periods and RHS boundaries. No IMX415 numeric timing copied. |
| Frame rate | Retain integer-fps and fps-times-1000 handling; add zero-timing guards to HDR GetFPS. |
| Exposure | Retain IMX334 SHR/RHS arithmetic; guard uninitialized line period/VTS before division. Actual limits remain unvalidated. |
| Gain | Same intlog10-based conversion structure; retain IMX334 bounds and register packing. |
| Grouped writes | Keep LEF as the shared HDR write owner and SEF notification as a no-op; clear dirty after the grouped update, as IMX415 does. |
| Orientation | Preserve IMX334 register addresses/tables; fix the vertical-bit shift and return I2C read failures. |
| Power / calibration / queries | Retain sensor-specific power sequence and callbacks. Stub query/calibration callbacks are not a claim of complete feature support. |

The four linear mode descriptors and base register tables are unchanged.
An extracted-function host test passed all four orientation combinations and
both I2C read-failure cases. IMX334, unmodified IMX335/IMX415 and sensor_config
again compiled with no compiler/MODPOST warnings. Latest IMX334 module SHA-256:
`3c5a7d08146ee2d4d51810720cfdfdab46d99e094ef9d520cec7ea9c9332b92f`.

Remaining checks include HDR mode-selection order and shared private-state
assumptions, physical DOL packing, long/short exposure limits, I2C write-error
recovery, orientation-dependent HDR timing, HDR IQ and Majestic integration.
The module has not been installed or tested on the camera. Do not treat the
reference driver's presence of a callback as proof of IMX334 compatibility.
